# 安全公告（2026 年 11 月）

简体中文 · [English](SECURITY_NOTICE_2026-11.md)

**一句话：** 桌面伴伴 **0.2.2** 修好了 2026-11-19 全面安全审查查出的问题。**之前的版本（0.1.0–0.2.1）都受影响，请更新到 0.2.2。** 这些问题都不是高危，目前也没有发现有人利用过。旧版本的下载包已经从 Releases 页面撤下。

同时，维护者改写了 Git 历史，删掉一个不该公开的文件。0.2.2 之前的每个提交都换了新编号，`v0.1.0`、`v0.2.0`、`v0.2.1` 三个标签也改指向新提交。如果你看到标签变了、担心仓库被人动过：原因就是这个，下面列出了全部差别，可以自己核对。**只下载 app 来用的，可以跳过 Git 那一节。**

## 谁受影响

- **所有人**：同一台 Mac 上的其他账户能让 app 起不来；任何程序发一条假的锁屏通知，就能让桌宠隐藏（低危）。
- **装了可选的本地聊天**：下表里和聊天有关的几条，包括模型进程的沙盒。
- **装了可选的朗读声音**：模型进程的沙盒；用 0.2.0 装的，还有旧的参考录音。

## 0.2.2 修了什么

| 问题 | 影响版本 | 严重程度 |
|---|---|---|
| **模型进程的沙盒能被绕出去。** 本地聊天和朗读进程运行第三方代码，原来的沙盒只禁了网络。进程里的代码能启动 `/usr/bin/open`，让沙盒外的程序联网，或者留下一个下次登录时会运行的文件。前提是固定版本的运行时或模型文件本身先有漏洞。现在这两个进程还不能启动别的程序、不能打开 app 或链接、不能发 Apple 事件、不能用麦克风和摄像头、不能改任何 app 的设置、不能用剪贴板，也只能往你临时目录里它们自己的文件夹写文件。 | 聊天 0.1.0 起，朗读 0.2.0 起 | 中 |
| **粘贴的文字能伪造「系统」消息。** 消息里出现 `<\|im_start\|>` 这类聊天模板记号时，会被当成真的角色分界；从 0.2.0 起，伪造的内容还可能留在「记住的关于你」里。现在 app 和聊天进程两边都会把它们换成无害的字符。 | 聊天 0.1.0 起 | 中 |
| **危机热线会被截掉或认不出。** 回复稍长，热线就会被截出气泡，中英文界面都会；繁体、拆开写和很多换个说法认不出。现在热线总是整句显示，回复被打断时也会给出。 | 聊天 0.2.0 起 | 中 |
| **从 0.2.0 升级后还在用旧的朗读声音。** 就是下面说的那段旧录音。0.2.1 只提示重新安装（2.5 GB）；0.2.2 会自动换成现在的声音，不用重新下载。 | 用 0.2.0 装的朗读声音 | 中 |
| **要你输入密码的回复会原样显示**；从 0.2.0 起，「记住的关于你」还会学进粘贴的文字和指令。 | 聊天 0.1.0 起 | 低 |
| **组件安装器下载没有大小上限，还会读 `~/.curlrc`。** 只在安装可选组件时有影响。 | 聊天安装器 0.1.0 起，朗读安装器 0.2.0 起 | 低 |
| **同一台 Mac 上的其他账户能让 app 起不来**（单实例锁放在公共的 `/tmp`）；任何程序发一条假的锁屏通知，就能让桌宠隐藏。 | 0.1.0 起 | 低 |
| **发布流程：** CI 检出代码后把有写权限的令牌留在磁盘上；发布内容检查连自己的测试样本都漏掉大半。 | — | 低 |

细节见 [0.2.2 更新记录](../CHANGELOG.md)。

## 为什么改写了 Git 历史

0.2.0 带了一段参考录音（`voice/companion_voice.wav`）和它的描述（`voice/companion_voice.json`），不适合公开发布。0.2.1 已经换成用 Qwen3-TTS 自带说话人 Serena 合成的样本，0.2.0 的下载包也撤了，但旧文件还留在 Git 历史里。为了不再继续分发，2026-11-19 改写了历史：

- 两个 0.2.0 提交里，删掉旧的 `voice/companion_voice.wav` 和 `voice/companion_voice.json`；
- 第一个提交之后的 7 个提交里，`scripts/audit_release.py` 各删掉两条内部检查项；
- 第一个提交（Initial commit）的文件完全没变。它换编号，只是因为创建时 GitHub 加上的签名在改写时没法保留，所以不再显示「Verified」。

作者、时间、提交说明都没变。新旧提交编号对照：

因为那段录音删掉了，`v0.2.0` 标签现在没法从源码构建，请用 0.2.2。

### 如果你在改写前克隆过这个仓库

**先别运行 `git pull`。** 已经运行过的，看第 1 步里的说明。

1. 先整体备份，再记下起点：
   - `git bundle create ../before-rewrite.bundle --all`（整个克隆的备份；里面还有被删的录音，请只留在自己电脑上）；
   - `git branch old-upstream origin/main`。
   如果你已经在改写之后运行过 `git pull` 或 `git fetch`，`origin/main` 已经是新历史了，改用旧编号：`git branch old-upstream 32be71d`；0.2.1 之前克隆的，用上表里 `git cat-file -t <编号>` 能显示 `commit` 的最新那个旧编号。
2. 拉取新历史：`git fetch origin --force --tags`（不加 `--force`，改过指向的标签会被拒绝）。
3. 核对差别：`git diff --stat 32be71d 5eca5a1`（或者表里同一行的新旧编号）只会显示 `scripts/audit_release.py | 2 --`；两个 0.2.0 提交还会多列出被删的两个录音文件。
4. 逐个分支看有没有自己的提交：`git log --oneline old-upstream..<分支>`。
   - 有输出：`git rebase --onto origin/main old-upstream <分支>`。
   - 没有输出、是 `main`：`git checkout main`，再 `git reset --hard origin/main`（会丢掉没提交的改动，请先另存）。
   - 没有输出、是别的分支：用 `git branch -D <分支>` 删掉。
5. 核对没有别的地方还连着旧历史：`git for-each-ref --contains c47a0f8 --format='%(refname)'` 应该只列出 `refs/heads/old-upstream`。
   - 列出了你自己的标签：`git tag -d <标签>`（需要的话在新提交上重新打）。
   - 列出了 `refs/stash`：先 `git stash pop` 拿回改动，剩下的用 `git stash drop` 删掉。
   - 清单里没有 `old-upstream`：说明它是在新历史拉下来之后才建的，用旧编号重做第 1 步，再做一遍第 4 步。
   清单里只剩 `old-upstream` 时，用 `git branch -D old-upstream` 删掉它。不要把它或备份文件推送、上传到任何地方。

如果你没按这些步骤、先运行了 `git pull`：默认多半会报 "refusing to merge unrelated histories"、"divergent branches" 或 "Not possible to fast-forward"；设了 `pull.rebase` 的可能直接成功、你的提交也在，但标签要做完第 2 步才会更新，第 5 步也照样要做。**任何时候都不要加 `--allow-unrelated-histories`**：那会把旧历史连同被删的录音合回来。如果你把旧历史推到了别处，请换成新历史，也请不要再上传被删掉的旧录音。

## 建议你做什么

1. **更新到 0.2.2。** 从 [Releases](https://github.com/Bf190t/mac-desktop-companion/releases) 下载，退出旧版后替换。设置、「记住的关于你」和已经装好的组件都会保留。
2. **用过本地聊天的**，打开「记住的关于你」看一眼，删掉不是你自己说的条目。
3. **用 0.2.0 装过朗读声音的**，0.2.2 会自己换成现在的声音（约 1–2 分钟，不用下载），换好之前用系统声音朗读。
4. **自己从源码构建、或者抄过这个项目代码的**，特别是沙盒配置和聊天模板处理，请换成 0.2.2 的写法。

## 核对 0.2.2 下载包

0.2.2 的 ZIP 和 `.sha256` 文件由仓库的 CI 按 `v0.2.2` 标签构建、上传，上传前会对打好的包再做一次发布内容检查。app 是 ad-hoc 签名，没有经过 Apple 公证；校验值只能确认你下到的和发布的文件一致，不能证明是谁做的。

## 用同样的方法查查你自己的 app

这次审查用的是同一位维护者开源的 [app-security-review](https://github.com/Bf190t/app-security-review)，一个给 Claude Code 和 Codex 用的 skill：只审查你自己的代码，在隔离副本里离线扫描，派几个审查员分别复现每一条问题，修完再让没写代码的复查员试着绕过。这次审查的经验也写进去了。
